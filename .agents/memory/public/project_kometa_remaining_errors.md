After confirming the 08-04/05 fixes held (see [[project_kometa_imdb403_addons_fix]]) and the Netflix overlay bug closed (see [[project_kometa_netflix_overlay_bug]]), Kometa's latest clean run (39m42s) still has a small residual error set, catalogued during Ryan's 2026-08-07 "known per-item asset issues" investigation:

- **5× "Collection ID missing on TMDb; add to franchise exclude list"** — from the `- default: franchise` collection block (`config.yml:12`). TMDB has deleted/merged these collections upstream. **This is the one genuinely config-fixable item** — Kometa's own error message tells you the exact fix (add the IDs to the franchise exclude list). Caveat: these IDs churn as TMDB curates its collection catalog, so this is somewhat whack-a-mole — expect new ones to appear periodically even after fixing the current batch. Not yet applied — flagged to Ryan, awaiting go-ahead (it's a config edit to shared production config).
- **3× "No Movie found for TMDb ID"** — sequential high-numbered IDs (17258xx range), consistent with recently-created TMDB records that were since purged as spam/duplicates. Transient, self-resolving, not worth chasing.
- **1× TVDb error on `tt3348258`**, inside the *Arrowverse (Timeline Order)* playlist — confirmed via grep that this ID is NOT in Ryan's own config files, meaning it's baked into Kometa's own bundled default playlist definition. An upstream Kometa data bug, not something fixable locally short of dropping that whole playlist.
- **1 CRITICAL error per night, different root cause each night** — 08-07 was a DNS failure resolving `datasets.imdbws.com` (IPv6-only records for that host — plausible transient IPv6 resolution hiccup, resolves fine when checked after the fact), 08-05 was a Plex connection-refused, 08-03/04 were the now-fixed IMDb 403s. All network/transient in nature, none tied to a specific media item — worth a closer look only if a single specific cause starts recurring night after night rather than rotating.
- **399× "No Items found in Plex"** — high count but benign: these are broad Kometa-bundled defaults (anime-studio collections like ufotable, bilibili, feel.) matching nothing because Ryan's library doesn't have that content. Not an error in any meaningful sense, just noisy default-template coverage.
- **4× Asset Warning** — 3 Hobbit films + Supergirl (2026): Kometa created the asset directory but Posterizarr never generated a poster for them. Small Kometa↔Posterizarr seam, not investigated further yet — see [[project_posterizarr]] for the Posterizarr side of the per-item asset investigation this was found during.
  - **RESOLVED 2026-08-07 — never a bug, just scheduling lag.** All 4 now have `poster.jpg` + `background.jpg` (written 11:02 AM PT). Kometa's Movies run creates the empty asset folders at **1:00 AM PT**; Posterizarr fills them at **11:00 AM PT** — a ~10-hour window in which the folders legitimately sit empty, and the original investigation simply sampled inside it. Proof it's not a discovery bug: that day's Posterizarr run created *exactly* 9 images — 4 posters + 4 backgrounds (the 3 Hobbits + Supergirl) + 1 Silo title card — i.e. those 4 items were the entire run. Posterizarr is incremental (only processes items lacking assets), so it picking up precisely the 4 gap items proves discovery works. **No fix needed; expect this warning on any title added between the two run times.**

**FRANCHISE EXCLUDE FIX APPLIED 2026-08-07** (Ryan-approved). The 5 dead TMDb collection IDs from the 08-07 08:00 run — `1729058, 1698578, 1677089, 1687719, 1704738` — added to `/opt/docker/appdata/kometa/config/config.yml` under the `- default: franchise` block (Movies library only; the TV Shows franchise default at line ~104 is commented out). Backup: `config.yml.bak-franchise-exclude-fix-20260807`.
Syntax was verified against Kometa's own source rather than guessed: `exclude` is a valid template_variable (`modules/meta.py:813`, listed in `dynamic_attributes` at line 23; `append_exclude`/`remove_exclude` also exist), and it filters IDs out of `auto_list` (`meta.py:955`) *before* the `validate_tmdb_ids` call that emits the error (`modules/tmdb.py:526`) — so the errors genuinely stop rather than being merely suppressed. Values are compared as strings (`meta.py:850` does `str(e)`), so bare ints in YAML are fine.
Validated with `docker exec kometa python3 kometa.py --validate --run-libraries Movies` → **structure PASSED** (Kometa 2.4.6). No restart required — Kometa re-reads config each run. **End-to-end confirmation still pending** the next scheduled 1 AM PT run; check that log for zero `Collection ID ... missing on TMDb` errors.
⚠️ **This is inherently whack-a-mole** — TMDb curators merge/delete collections continuously, so new dead IDs will appear eventually. New IDs showing up later is expected churn, *not* evidence this fix failed; just append them to the same list.

**How to apply:** the franchise-exclude list is now the established, repeatable fix — when new "add to the franchise exclude list" errors appear, grep the latest `meta.log` for the IDs and append them to the existing `exclude:` block (back up first). Everything else here is upstream/transient (don't chase). Don't re-treat the Netflix overlay bug, the 08-04/05 issues, or the Hobbit/Supergirl asset seam as still open — all confirmed closed.
